Spring Framework 核心笔记

一、IoC 容器
Spring 框架的基石是控制反转容器。容器在启动阶段读取配置元数据（XML、注解或 Java Config），实例化并装配 Bean。所谓控制反转，指的是对象的创建权从程序代码转移到容器，开发者不再主动构造依赖。依赖注入有三种方式：构造器注入、Setter 注入和字段注入。官方推荐构造器注入，因为它能保证依赖不可变且在对象创建完成时就绪，也方便写单元测试。字段注入虽然写法最简洁，但隐藏了依赖关系，不利于测试时替换实现。

二、Bean 的作用域与生命周期
Bean 默认是单例（singleton），容器内共享一个实例；prototype 作用域每次注入都创建新对象。生命周期回调可以通过 @PostConstruct 和 @PreDestroy 标注，也可以实现 InitializingBean 与 DisposableBean 接口。循环依赖是单例 Bean 的常见问题：构造器注入的循环依赖会直接启动失败，字段注入则可以靠三级缓存提前暴露半成品对象解决。

三、构造型注解的语义
@Component 是所有受管组件的通用标记。@Service 标记业务层，@Repository 标记持久层，@Controller 标记表现层。这几个注解在组件扫描阶段完全等价，都会被注册为 Bean；真正的差异在于:@Repository 会启用持久层异常转换，把不同数据库的底层异常统一包装成 Spring 的 DataAccessException 体系，让业务代码不必针对特定数据库写异常处理。@Controller 配合视图解析器返回页面，而 @RestController 会把返回值直接写入响应体。

四、AOP 与代理
面向切面编程用于把日志、事务、权限等横切逻辑从业务方法中剥离。Spring AOP 默认使用 JDK 动态代理（目标实现接口时）或 CGLIB（目标无接口时）。@Transactional 就是基于 AOP 实现的：方法进入时开启事务，正常返回提交，抛出运行时异常回滚。要注意自调用问题——同一个类中方法互相调用不会经过代理，事务注解会失效。
